# Design 003 — Testing & Benchmarks

Status: **draft for approval** · Scope: every way correctness and speed are verified

The rule from PLAN.md §2: **tests land with the feature, in the same commit.**
This doc defines what "tests" means so that rule is enforceable.

## 1. Test taxonomy

| Layer | Lives in | Framework | What it covers |
|-------|----------|-----------|----------------|
| Unit | `tests/unit/` | Catch2 (C++) | Lexer token streams, parser AST shapes, value repr, string interning, GC invariants, register allocator |
| Conformance | `tests/conformance/` | golden files + `tests/run.py` | Observable behavior of every language feature |
| Errors | `tests/errors/` | golden diagnostics | Every error code: bad syntax, type errors, arity, runtime traces |
| Automation | `tests/automation/` | golden mock-platform logs | Every command statement against the mock backend |
| Fuzz | `tests/fuzz/` | libFuzzer + ASan/UBSan | Lexer, parser, and compile+run-with-budget never crash on arbitrary bytes |
| Benchmarks | `tests/bench/` | custom runner | Speed vs CPython (and past-self) |
| Token cost | `tests/tokencost/` | tiktoken-based report | Syntax efficiency for LLM generation |

## 2. Conformance harness (the workhorse)

A conformance test is **one `.syn` file**; expectations are embedded as
comments so a test is a single self-describing artifact:

```syn
# test: arithmetic/floor_division
say 10 // 3
# expect: 3
say -7 // 2
# expect: -4
```

Error tests assert the stable code + location, not wording:

```syn
# test: types/no_string_int_add
say "a" + 1
# expect-error: E0012 @ 2:5
```

Automation tests assert the mock platform log:

```syn
# test: commands/mouse_move
move mouse to 300, 400
# expect-platform: MouseMove(300, 400)
```

`tests/run.py`:
- discovers `tests/{conformance,errors,automation}/**/*.syn`, runs each under
  the release binary, diffs against expectations
- modes: `--update` (bless new goldens, prints diff for review), `--vm-trace`,
  `--gc-stress` (re-runs the suite with `SYN_GC_STRESS=1`)
- also re-runs the whole conformance suite under **ASan** in CI
- registered in CTest so `ctest` runs everything: unit + golden + smoke

**Coverage discipline:** every grammar production in `docs/spec/grammar.ebnf`
must be named by at least one conformance file; `tests/run.py --coverage`
cross-references the two and fails on gaps. That's the mechanical enforcement
of "implement something new → implement a test for it."

## 3. Fuzzing

- `fuzz_lexer`, `fuzz_parser`: arbitrary bytes → must not crash/UB/hang.
- `fuzz_exec`: parse + compile + run with instruction & allocation budget.
- Corpus seeded from the conformance suite; crashers get minimized and
  checked in as regression tests in `tests/errors/regressions/`.
- CI runs 60s per target per PR; longer scheduled runs nightly.

## 4. Benchmark system (the Python comparison)

### Structure

Each benchmark is a directory with **equivalent idiomatic implementations**:

```
tests/bench/suite/
├── fib/            fib.syn          fib.py          (recursion + call overhead)
├── nbody/          …                …               (float math, loops)
├── binary_trees/                                    (allocation + GC pressure)
├── spectral_norm/                                   (inner-loop arithmetic)
├── string_build/                                    (interpolation/concat, interning)
├── map_stress/                                      (dict insert/lookup/delete)
├── list_sort/                                       (collections + comparisons)
├── method_calls/                                    (dispatch + inline caches)
├── closures/                                        (upvalue capture/access)
└── startup/                                         (cold start to first output)
```

Workloads are sized for 0.5–3s wall time in Synapse release builds, verify a
checksum of their result (a benchmark that computes the wrong answer fails),
and take a scale parameter so the same script smoke-runs in CI in <50ms.

### Runner (`tests/bench/run.py`)

- ≥10 timed runs after 3 warmups; reports **median, IQR, and ratio vs
  CPython**; refuses to compare unless both sides verified their checksum
- `--compare python3 [--compare lua]`, `--json out.json` for history
- `--against baseline.json`: compares to a stored baseline, **exits nonzero on
  >5% regression** — this is the CI perf gate (run on a dedicated label/job,
  not on shared noisy runners, with results posted to the PR)
- environment capture in every report: CPU model, governor, compiler, flags,
  commit hash — numbers without provenance are not numbers

### Reporting

`docs/BENCHMARKS.md` is generated by `run.py --report`, never hand-edited:
table of benchmark × {Synapse, CPython 3.x} × median ± IQR, plus the history
sparkline per benchmark from committed JSON snapshots in `tests/bench/history/`.

## 5. Token-cost benchmark (unique to Synapse's mission)

`tests/tokencost/run.py`:
- corpus = `examples/**/*.syn` + paired `examples/**/*.py` equivalents
- tokenizes both with `tiktoken` (cl100k/o200k) as a proxy for modern BPE
- reports total + per-task token counts, Synapse:Python ratio
- CI fails if a grammar change regresses the corpus cost >2% — syntax
  decisions get the same regression discipline as runtime perf

## 6. CI matrix (GitHub Actions)

| Job | Build | Runs |
|-----|-------|------|
| linux-gcc-debug | Debug | unit + conformance |
| linux-clang-release | Release | unit + conformance + bench smoke + tokencost |
| linux-clang-asan | ASan+UBSan | unit + conformance + `--gc-stress` |
| fuzz-smoke | fuzz preset | 60s per fuzz target |
| lint | — | clang-format, clang-tidy, spec/test coverage cross-check |

All jobs required to merge. Nightly: extended fuzz (30min/target) + full
benchmark run against the rolling baseline.

## 7. Determinism

The v1 `check_determinism.py` idea is kept and promoted: CI runs the entire
conformance suite twice and byte-compares all output (including mock-platform
logs and error messages). Map iteration order is **insertion order by spec**
(like Python 3.7+) precisely so this check is meaningful.
